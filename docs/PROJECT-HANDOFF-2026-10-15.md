## بررسی‌های واقعاً انجام‌شده

- بررسی syntax جاوااسکریپت و `git diff --check` موفق بود.
- `node scripts/check-frontend.cjs` موفق بود: بارگذاری خودکار دسته، سؤال‌های پویا، پاسخ boolean، نمایش توصیه، نبود قاعده و امکان تلاش مجدد با API شبیه‌سازی‌شده.
- ۳۱ تست موجود بک‌اند در ۷ کلاس اجرا شدند: صفر failure/error/skip و BUILD SUCCESS. مجموعه شامل DecisionServiceTest و کنترلرهای Decision، Category، Question، AnswerOption، Location و ItemLocation بود.

- هشدارهای موجود Lombok دربارهٔ initializer فیلدها در @Builder مشاهده شد؛ در این کار منطق Java تغییر داده نشد.

## کارهای باقی‌مانده به ترتیب پیشنهادی

1. نسخهٔ مشترک را با PostgreSQL محلی اجرا و جریان واقعی UI/API را بررسی کنید. راهنما: `README.md` و `backend/docs/local-preview.md`.
2. با نوشین قرارداد جست‌وجوی وسیله را تثبیت کنید. مدل Item و سرویس موجود است اما کنترلر جست‌وجوی نام وسیله در بکاپ وجود ندارد. `/api/items/search?q=...` پیشنهاد است، نه API فعلی.
3. بعد از جست‌وجوی واقعی، itemId معتبر و categoryId را از سرور دریافت و در تصمیم استفاده کنید؛ نگاشت حدسی نام وسیله به ID انجام نشود.
4. وضعیت required بودن سؤال‌ها را هماهنگ کنید. در دادهٔ نمونه functional و repairable هر دو اجباری‌اند؛ پنهان کردن repairable برای وسیلهٔ سالم به هماهنگی اعتبارسنجی نیاز دارد.
5. مراکز را با وسیله و action توصیه سازگار کنید. `/api/items/{itemId}/locations` موجود است اما صرفاً ارتباط وسیله با مرکز برای توصیهٔ تعمیر/اهدا/بازیافت کافی نیست.
6. دادهٔ معتبر وین، منبع/زمان به‌روزرسانی، نقشه و فیلتر منطقه را تکمیل کنید. مراکز قبلی فرانت و قواعد demo دادهٔ واقعی تأییدشده نیستند.
7. مستندات API را با کد هماهنگ کنید: برخی مسیرهای مراکز در docs هنوز برنامه‌ریزی‌شده معرفی شده‌اند، ولی کنترلرشان موجود است.
8. پس از بررسی نسخهٔ مشترک، ادغام با main جداگانه انجام شود. تا این یادداشت PR یا merge ایجاد نشده است.
